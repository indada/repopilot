# RepoPilot 1.8.0

RepoPilot 1.8.0 connects typed AI decisions to independent engineering evidence, human review and controlled policy iteration. Codex continues to generate tests and propose repairs through the OpenAI Codex SDK. The controller retains execution authority, budgets, recovery and publication gates.

## What's new

- **Jev decision integration**: optional TypeSafe Choice, Score and Noul judgments classify trusted Issue requests, estimate change risk, assess testability and retain urgency advice. Shadow mode records recommendations; opt-in gate mode defers uncertain new intake. Pinned-input caching, bounded retries and a separate persistent daily ledger cover provider calls.
- **Outcome linkage**: immutable observations connect decisions with reproduction reports, goals, repair PRs and post-merge results. Engineering success never automatically becomes a low-risk human label.
- **Human-reviewed decision evaluation**: fixed suites pin input/evidence digests and exact label revisions. Offline replay measures false allows, false reviews, optional label agreement, observed usage and time without provider calls.
- **Threshold comparison and sweeps**: compare the same frozen dataset across policies and inspect nine confidence/testability combinations before choosing a version.
- **Versioned policies**: immutable specifications, evaluation-gated activation previews and explicit rollback preserve previous settings and transition history. The first activation snapshots the configured baseline. Policy changes never replenish usage or goal budgets.
- **Operator requests during service execution**: queue manual labels, retries and policy changes while the controller runs. Each request is revalidated at a controller boundary and receives a durable applied/rejected receipt.
- **Local read-only console**: `dashboard` displays candidates, decisions, DAGs, budgets, policy state, event queues and operator receipts. It binds to loopback, uses an independent session token and exposes no write routes, provider secrets or raw logs.

The persistent GitHub service, signed Webhooks, evidence-driven candidate queue, bounded DAG parallelism, repository rules, multilingual test evidence, PR maintenance and crash recovery remain available. No decision or dataset label can waive stable reproduction, trusted-source authorization, scope restrictions or independent verification. Merging and deployment remain maintainer decisions.

## Downloads

Portable packages include Node.js 22, production dependencies, native launchers, source files, examples and documentation for Linux x64/ARM64, Windows x64 and macOS Intel/Apple Silicon. Extract the entire archive and verify it against `SHA256SUMS.txt`. Use `./repopilot` on Linux/macOS or `.\repopilot.cmd` on Windows. Git and Docker with Linux containers remain external prerequisites. Packages are command-line tools and are not code-signed or notarized.

The matching Agent image is `ghcr.io/indada/repopilot-agent:1.8.0` for Linux amd64/arm64. `OPENAI_API_KEY` remains the Codex credential. Optional Jev calls use a separate `TYPESAFE_API_KEY` kept in the controller.

## Upgrade

Stop the old controller, extract 1.8.0 into a separate directory and retain the existing configuration and complete data directory. Pull the matching Agent image, update `agent.image`, and run `--version` and `doctor` before restarting. Preserve prior evidence when execution-policy/runner/Agent changes require a new goal configuration.

This release includes the Jev features developed for 1.7.0; an intermediate installation is not needed. Jev remains disabled when its configuration is absent, and managed policy activation requires explicit `decision.useManagedPolicy=true`. Supplied examples leave decision calls, repair and publication disabled. Review and retry requests do not approve a candidate, and policy replay does not contact a model.

```sh
./repopilot dashboard --config config.local.json
./repopilot decisions outcomes --config config.local.json
./repopilot decisions requests --config config.local.json
./repopilot policies status --config config.local.json
```

Use `.\repopilot.cmd` instead on Windows. Follow the [decision governance guide](https://github.com/indada/repopilot/blob/v1.8.0/docs/DECISION-GOVERNANCE.md), [Jev setup guide](https://github.com/indada/repopilot/blob/v1.8.0/docs/JEV-DECISIONS.md) and [portable quickstart](https://github.com/indada/repopilot/blob/v1.8.0/docs/QUICKSTART.md) included in every package.
